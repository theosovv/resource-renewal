# ADR-0003: Идемпотентность провайдера и recovery после неопределённого ответа

- Статус: Accepted
- Дата: 2026-11-20

## Контекст

Первый POST имитатора сохраняет операцию, но возвращает `503`. Клиент не может узнать результат только по этому ответу. Повторный POST с новым ключом создал бы недопустимый дубликат. После локального подтверждения также возможен сбой до фиксации результата.

## Решение

1. Генерировать UUID `operation_key` при создании заявки и хранить его постоянно.
2. Всегда использовать этот ключ для POST и percent-encoded GET.
3. Формировать payload исключительно из immutable request snapshot: `resource_id`, `period_months=1`, `amount_minor`, `currency`.
4. Применять persistent execution protocol `POST → RECONCILE → POST`, не более трёх автоматических POST в cycle.
5. POST-attempt резервировать в БД до HTTP; GET не учитывать как POST.
6. После третьего uncertain POST выполнить RECONCILE, затем перейти в `NEEDS_ATTENTION`, если результата всё ещё нет.
7. После provider `200` проверить status, started count и соответствие payload, затем финализировать БД одной транзакцией.
8. При recovery просроченного RUNNING сначала делать RECONCILE, а не безусловный POST.
9. Manual retry использовать тот же ключ, начинать с GET и новый cycle попыток.

Подробности: [reliability.md](../reliability.md).

## Последствия

- Многократные HTTP-запросы допустимы и ожидаемы.
- Одна заявка не должна приводить к более чем одной provider operation.
- Crash после reservation может conservatively расходовать попытку, даже если запрос фактически не ушёл.
- При неповторяемом conflict разрешён ранний переход в attention.
- Перезапуск provider во время операции остаётся вне гарантии.

## Альтернативы

- **Новый ключ при каждом retry:** отклонено, допускает повторное внешнее продление.
- **Только повторный POST без GET:** допустимо по заданию, но выбранный GET позволяет быстрее получить уже сохранённый результат и явно проверить recovery.
- **Бесконечные retry:** отклонено, задание требует attention после трёх POST.
- **Гарантия exactly-once для любого API:** невозможна в рамках выбранной границы и отклонена как некорректное обещание.
